### 项目与工具雷达增量

**S-006｜SQLite Vec1：官方路线上的原生 ANN 向量搜索扩展。** Vec1 通过 SQLite virtual table 提供 ANN，支持 L2/cosine，当前采用 IVFADC + OPQ，单 C 文件、无外部依赖，并针对 x86 AVX2 / ARM NEON 优化。值得注意的是它的 roadmap 明确写着“testing is insufficient”，且 HNSW / DiskANN 等现代图索引仍处于后续探索，因此目前更适合视为 SQLite 原生向量能力的早期信号，而非成熟向量数据库替代。
- Problem solved: 在 SQLite 内直接完成近似向量检索，减少嵌入式/本地应用引入独立向量数据库的复杂度。
- Why now: 官方 SQLite 域名上的实现已到 0.7，且 1.0 前功能范围基本冻结。
- What is interesting: 单文件 C 扩展、无外部依赖、跨 x86/ARM SIMD，非常贴合 local-first / embedded AI。
- Contrarian angle: “本地 RAG 必须再带一个向量数据库”可能越来越不成立，但 Vec1 当前测试和优化仍不足。
- Discussion signal: 当前 HN 讨论尚低热度，暂时没有足够社区样本形成共识。
- Limitations: 官方明确称 testing insufficient；多线程、HNSW/DiskANN、更多数据类型等仍在 roadmap。

**S-007｜Maritime：把“每个 Agent 一台长期存在的机器”产品化。** Maritime 为每个 Agent 提供独立 Firecracker micro-VM、持久磁盘和浏览器登录状态，并主打休眠/恢复来降低长期在线 Agent 的成本。官方页面称新 VM 约 0.5 秒启动、休眠 VM 约 0.6 秒恢复，并给出“典型 Agent 每天只活跃 11 分钟”的内部建模；这些性能和 fleet 数据目前均属于作者自述，未找到独立 benchmark。
- Problem solved: 长期 Agent 需要文件、包、浏览器登录、凭证与任务状态跨会话持续存在。
- Why now: Manus/OpenClaw/Muse 一类持续在线 Agent 已把“Agent 需要自己的电脑”从架构设想推向产品竞争。
- What is interesting: 它不是 serverless request，而是长期 VM + sleep/restore，把 idle cost 当一等问题。
- Contrarian angle: 长期 Agent 的核心基础设施可能更像“可休眠的个人电脑 fleet”，而非函数调用平台。
- Discussion signal: HN 当前刚发布，讨论样本不足。
- Limitations: 关键性能、成本和 adoption 数据主要来自厂商自身；凭证隔离、出站权限和 fleet 安全仍需进一步核验。
