#### X-001｜Scion：Agent 把代码基础设施也卷进效率革命
- 判断：推荐发布；受众：Coding Agent、Harness、DevInfra；时效：10-13 官网新文章。
- 为什么值得发：真实工程案例可延展为 RepoOps 的 Cost/Task、审查意图和可追溯性；勿泛化为 Git 已过时。
- Source: https://www.anthropic.com/engineering/redesigning-source-control
- HN: https://news.ycombinator.com/item?id=50073633
- Key comment: https://news.ycombinator.com/item?id=50076155
- Evidence: https://sapling-scm.com/ ; https://news.ycombinator.com/item?id=50077469
- 事实/推断：架构 verified_fact；30k/日及收益 author_claim；普适性 inference。
- A 极简判断版：Anthropic 被 Coding Agent 的产出速度倒逼，自己造了 Scion 版本控制系统。提交、diff、blame 和按需 checkout 围绕在线 Agent 重设计。Agent 的瓶颈，已经扩散到代码仓库和 CI。
- B 个人观察版：Scion 工程复盘值得看。Anthropic 自述代码合并量暴涨，传统 Git 镜像体系成本太高，于是改成服务端 changeset、分层缓存与 API 查询。未来 Harness 评测或许还得算 RepoOps 的成本。
- C 反直觉讨论版：有人问，Agent 每天写这么多代码，还需要版本控制吗？我反而觉得更需要。没有历史、blame、bisect，Agent 更容易修了又改回去。真正值得优化的是追溯成本和审查质量。

#### X-002｜Parsimony：测量 Coding Agent 到底多写了多少代码
- 判断：推荐发布；受众：模型评测、Harness、独立开发者；时效：10-14 新 Show HN。
- 为什么值得发：一个可复制的评测指标和它明显的反例，适合高信噪比技术讨论。
- Source: https://github.com/La5u/Parsimony
- HN: https://news.ycombinator.com/item?id=50077619
- Key comment: https://news.ycombinator.com/item?id=50081136
- Evidence: https://parsimony.lasu.dev/ ; https://www.swebench.com/
- 事实/推断：净语法单元方法 verified_fact；更少即更好 unknown。
- A 极简判断版：HN 发现一个小而有趣的 Coding Agent 评测 Parsimony。它从 benchmark patch 中计算净增加的语法单元，想知道模型修好问题时到底多添了多少代码。测试通过之后，维护成本也值得关注。
- B 个人观察版：我现在看 Coding Agent，也越来越关心任务完成后仓库变成什么样。Parsimony 很朴素：同样通过测试，哪个模型留下的额外代码更少？指标还不完美，但这条研究路线值得继续做。
- C 反直觉讨论版：“代码越少越好”本身也会被刷榜：直接删除、写得晦涩，都能让净增量更漂亮。Parsimony 的价值是把问题摊开，提醒我们把变更范围、可维护性和回归成本一起测。

- A 极简判断版：HN 上一个有创意的小网站 Guitoro：打开浏览器，普通键盘就能弹吉他。左手按和弦、右手扫弦，还有伴奏和录音。几乎不需要教程，点开就能玩。值得试试。
- B 个人观察版：Guitoro 的交互很值得独立开发者学习。先让用户用键盘弹出声音，再慢慢探索和弦、音色、伴奏和录音。产品初次体验的门槛越低，传播就越有机会。
- C 反直觉讨论版：谁说不会弹乐器就不能演奏？HN 有用户把歌曲转成键位谱，直接像打字一样弹出来。Guitoro 这种借用已有技能创造新体验的玩法，可能比堆一大堆功能更有意思。
