- Problem solved: 高频、低延迟、结构化决策，以及图片输入 / bounding-box 这类不需要长文本生成的任务。

**S-005｜RPKI adoption：互联网路由安全在 2026 出现明显台阶式跃升。**
- Problem solved: RPKI/ROA 验证某 ASN 是否被授权宣告某 IP prefix，降低 BGP route hijack / misconfiguration 风险。
- Why now: IPinfo 基于 RouteViews / RIPE RIS 等数据报告，RPKI-valid routed prefixes 从 2025-09 的 54.0% 上升到 2026-09 的 70.3%；前两年每年只增加约 3–4 个百分点。
- What is interesting: 报告称中国 IPv4 valid routes 从 3.7% 升到 83.0%，按 address 计贡献了全球接近 60% 的增长；说明安全协议 adoption 可能由少数超大网络/国家的集中升级快速改变全球曲线。
- Contrarian angle: Internet core security 的改进经常很慢，但 adoption 一旦跨过运营商/监管/基础设施阈值，增长可以突然加速。
- Discussion signal: HN 当前讨论量尚小，未形成高质量分歧。
- Limitations: 70.3% 是 IPinfo 对公开 collectors 的分析，不等于“70% 流量都安全”；RPKI 也只覆盖 origin validation，不能解决所有 BGP path 问题。

### 热点讨论与反直觉观点

**D-001｜Muse Spark Open 评论区最有价值的争论：reasoning level 不是排名，生产评估应看完整 cost/time/quality curve。**
- Central question: open-weight / frontier agent 模型应该如何公平比较。
- View A: 只比较最高 reasoning 会偏离高频生产使用，因为很多团队实际使用 low / medium effort 来控制延迟和成本。
- View B: reasoning labels 本身不可直接跨模型比较，provider 的 low / medium / high 是不同内部预算。
- Converging point: HN 多条高信息量评论认为应画 task success / quality 对 total cost 或 elapsed time 的曲线，让不同 effort 都成为 curve 上的点。
- Source: https://research.meta.ai/blog/muse-spark-open
- HN: https://news.ycombinator.com/item?id=50107379
- Key comments:
  - https://news.ycombinator.com/item?id=50107379#50107447
  - https://news.ycombinator.com/item?id=50107379#50107814
- Evidence type: community_evidence + inference
- Current judgment: “模型智力”越来越不适合用单 benchmark 单 effort 表达，完整任务的 Pareto curve 更接近实际选型。

**D-002｜Jev Trolley Problem：Decision Model 的概率输出不能被误读成“知道自己为什么这么选”。**
- Central question: 输出 choice probability 的 Decision Model 是否更容易解释 / 更可靠。
- Evidence: 该实验覆盖 14 个模型、5,240 setups、多个 wording/order；Jev 的 3 次运行有 361/5,240 setups 跨过 0.5 决策阈值。作者同时把方法限制、分析计划与原始分数公开，并明确这些是“reported probabilities”，不是道德正确性的概率。
- Key discussion: HN 评论对模型是否在隐含“服务器未来还能救更多人”提出替代解释；作者随后追加 48 个 prompt 重跑，结果并未支持这一解释。这种“评论提出反例 → 作者现场补实验”比哲学结论本身更有研究价值。
- Source: https://zachlandes.com/trolley-problem/
- HN: https://news.ycombinator.com/item?id=50106023
- Key comment: https://news.ycombinator.com/item?id=50106023#50108170
- Evidence:
  - https://zachlandes.com/trolley-problem/
  - https://news.ycombinator.com/item?id=50106023#50108170
- Evidence type: verified_fact（实验方法与重跑）；community_evidence（替代解释）；inference（对 Decision Model 评测的启发）
- Current judgment: 对 decision API，calibration、prompt stability、counterfactual tests 都应进入 Harness eval，不该把单次概率当可解释性。

硬件商业化有个边界很值得观察。Withings 现在把第三方健康数据同步放进订阅，新账号受影响。设备卖一次，服务长期收费可以理解，但互操作能力一旦收费，用户对“数据到底属于谁”的感受会完全不同。

C｜反直觉讨论版
订阅最容易被接受的是持续产生的新价值，最容易引发反弹的可能是把原本基础的能力重新收费。Withings 这次把 Apple Health / Health Connect 同步放进会员，就是一个很典型的边界测试。
